Python/C decoder differential regression
========================================

The protocol review backend decodes security messages with the
asn1tools Python codecs, while devices decode them with the C decoders
generated by asn1tools. This regression feeds both sides the same
finite, seeded corpus of valid, truncated, mutated and random inputs
and checks that they agree, so a malformed security message can never
silently decode to different fields on the two ends.

What is compared
----------------

For both OER and UPER, per corpus input:

* accept/reject must match,
* on accept, the consumed byte length must match, and
* on accept, all decoded fields must match; for valid seeds the fields
  and consumed length are additionally checked against the
  independently known expected values (the values that were encoded).

Only the intersection of semantics implemented by both decoders is
compared:

* The schema (``secmsg.asn``) only uses features the C generator
  supports: constrained integers, nested CHOICE, variable-length arrays
  (SEQUENCE OF with SIZE constraints) and optional fields.
* The generated C decoder enforces only what must fit its fixed-size
  output structs (SEQUENCE OF capacity, variable OCTET STRING buffer
  size). ``c_capacity_ok()`` in ``differential.py`` mirrors exactly
  those checks on the Python side.
* The C decoder does **not** enforce ASN.1 integer ranges or SIZE
  minimums on decode (e.g. it accepts 137 for ``INTEGER (0..3)`` in
  OER). Value-range validation is therefore outside the compared
  intersection and remains the backend's own responsibility.

A crash on either side is never counted as agreement; if both sides
crash the case is recorded as a ``both-crash`` divergence.

Divergences
-----------

Every divergence is stored as one JSON file containing the minimal
reproducing input bytes (greedily minimized), both outcomes and the
codec, plus a copy of the (already minimal) schema, in the divergences
directory.

Running
-------

As a script (keeps the build dir and prints its location)::

    python3 tests/differential/differential.py --build-dir /tmp/secmsg-diff

As part of the test suite (builds in a temporary directory, persists
divergence records to ``tests/differential/divergences/`` on failure)::

    python3 -m unittest tests.test_c_differential

Files
-----

* ``secmsg.asn`` -- minimal security-message schema.
* ``harness.c.tmpl`` -- C decode harness template; ``@NS@`` is replaced
  with the codec namespace. Always passes the exact input length and
  the real output struct to the decoder, poisons the struct before
  decoding, and never fabricates fields on error.
* ``differential.py`` -- corpus generation, comparison, minimization
  and divergence records.
