`verify_host_key: :accept_new` now registers a new host key only after persisting it under an exclusive lock on the known_hosts file, so concurrent connections to the same new host can't store two different keys, and a key that can't be written is refused with `Net::SSH::HostKeyWriteFailed` instead of being trusted only in memory. A key already registered in any configured file, including a global one, is accepted when it matches and raises `HostKeyMismatch` when it differs; files are only appended to, preserving comments and other hosts' entries.
