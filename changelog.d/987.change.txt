Added `:algorithm_policy`, an optional strict negotiation policy (see `Net::SSH::Transport::AlgorithmPolicy`) that constrains which combinations of kex, host key, encryption and MAC algorithms a session may settle on. The policy is applied after the `:kex`/`:host_key`/`:encryption`/`:hmac` lists (including ssh_config values) are composed, so compatibility options like `:append_all_supported_algorithms` cannot re-add algorithms it forbids. It governs the initial key exchange and every rekey, fails before any authentication data is sent when no allowed combination can be negotiated, and logs the negotiated algorithms with the rule that accepted them (never key material or authentication data).
