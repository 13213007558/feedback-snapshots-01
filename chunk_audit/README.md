# 窗口化 YARA 扫描的静态预检（基于 Plyara）

把文件切成带重叠的滑动窗口、对每个窗口单独跑 YARA 时，跨在窗口边界上的匹配会
丢失，从而产生**漏报**。本包在**不扫描任何真实样本、不依赖额外 YARA 引擎**的前
提下，仅用 Plyara 的解析结果做有限静态预检，判断给定窗口策略
（窗口大小 `W`、步长 `S`）会让哪些规则漏报，并用一个独立的纯 Python 有限匹配器
在**合成字节缓冲**上产出漏报见证。

## 核心几何结论

相邻窗口为 `[kS, kS+W)`，保证重叠长度

```
G = W - S + 1
```

对一个**所有匹配长度都不超过 `G` 字节**的模式，任意一次匹配都会被至少一个窗口
完整包含（取起点所在窗口或其下一窗口即可证明）。反之，若模式存在长度 `> G` 的
匹配，则可把该匹配的起点放在 `kS+W-1`，使其跨越非重叠边界而不被任何窗口完整包
含——这正是有限匹配器构造的见证。

因此判据是模式**可证明的最大匹配长度**，而不是模式文本本身的长度。

## hex 模式的可证明长度

`hex_patterns.py` 把 hex 字符串解析为 AST，逐节点给出 `min_length/max_length`：

- 固定/通配半字节（`AA`、`??`、`D?`）：恒为 1 字节；
- 固定跳距 `[n]`：长度 `n`；区间跳距 `[m-n]`：长度 `m..n`；
- 开放跳距 `[n-]`、`[-]`：`max_length = None`，即**无界**，规则保持未决；
- 交替组 `(a|b)`：取各分支最小/最大值（min 取 min、max 取 max）；
- 序列：各节点长度相加。

文本字符串按字面字节数（`wide` 翻倍，`xor`/`nocase`/`fullword` 不改变长度）；
`base64`/`base64wide` 因匹配依赖上下文编码，按无界处理并保持未决。正则仅在量词
全部有界（`?`、`{n}`、`{m,n}`，无 `*`/`+`/`{n,}`）时给出可证明跨度，否则未决。

## 三类结论

- `safe`：能触发规则的每个模式最大匹配长度都 `<= G`，且条件只使用受支持的、与
  位置无关的布尔子集；可证明任何匹配都落在某个窗口内。
- `at_risk`：存在可证明超过 `G` 的匹配长度（单模式跨边界），或条件是多个不同字
  符串的 `AND`（每条字符串都短也**不能**宣称可分块，因为还要求它们落在同一窗
  口）。有限匹配器给出跨边界见证或分离见证。
- `undecided`：开放跳距/无界正则/base64 等无界模式，或条件包含 `at`/`in`/
  `filesize`/`@`/模块函数/`for ... :`/需要跨窗口计数的 `#a` 比较等需要全局偏移或
  全文件关系的构造。这类规则不下安全结论。

受支持的条件子集：字符串引用 `$a`、存在性计数 `#a > 0`、`any/all of ...`，以及
`and/or/not` 与括号。`at`/`in` 会被解析为带原因的 Unsupported 节点（窗口内偏移会
被重置，全局偏移语义不成立），而不是导致解析失败。

## 有限匹配器

`matcher.py` 仅实现上述有界子集：hex（回溯枚举区间跳距与交替的所有端点）、文本
（ascii/wide/nocase/xor/fullword）。它对同一缓冲分别做：

1. 整份字节扫描；
2. 对 `windows_for` 生成的每个窗口单独扫描，再把局部匹配映射回全局坐标。

两者之差即漏报匹配，输出 `(start, end)` 与被跨越的边界作为见证。所有缓冲均为合
成夹具，分析器本身不读取真实样本。

## 运行

```
.venv/bin/python examples/run_chunk_audit.py
.venv/bin/python -m pytest -o addopts= -q tests/test_chunk_audit.py
```

演示给出三个对照：短模式跨边界漏报、两个短模式相距很远导致 `AND` 规则丢失、以
及最大长度不超过重叠量的可证明安全规则；同时展示开放跳距与 `filesize` 规则保持
未决。
