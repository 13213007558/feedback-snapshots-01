# strict2 differential artifacts

Generated by the grammar-driven differential harness. Regenerate with:

```sh
bundle exec rake strict2:report
```

| File | Purpose |
| --- | --- |
| `report.md` | Every corpus template with its lax / warn / strict / strict2 execution fingerprint. |
| `checklist.md` | Actionable, template-level migration items grouped by grammar axis. |

## Method

- Oracle: a counting tag (`diff_tag`) and counting filters (`diff_f1`, `diff_f2`, `diff_f3`)
  that record their name/argument shape and return their input unchanged.
- A template is observed in `:lax`, `:warn`, `:strict`, and `:strict2`.
- `execution_change` means both parsers accept but different extensions actually run.
  On this corpus that count is **0**: strict2 acceptance never silently changes
  which tags/filters execute.
- Text inside `{% raw %}` / `{% comment %}` is emitted or discarded as text and is
  never counted as a callback, so probe-looking text there cannot fake capability.
- `:warn` is a hybrid: tags fall back from strict2, variables fall back from strict,
  and `when` clauses use the lax parser. Four corpus entries are rejected by strict2
  yet produce no warning. See the checklist's "Warn-mode caveat".

## Limitations

- The corpus is minimal and synthetic; it targets parser grammar, not theme-specific
  custom tags.
- The harness registers its own filter module. It does not exercise application
  filters, so re-run the same differential with your production filter module before
  switching a live environment.
